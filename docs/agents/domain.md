# Domain Docs

Single-context repo: one `GLOSSARY.md` at the root and ADRs in `docs/adr/`.

- Before working in an area, skim `GLOSSARY.md` and any ADRs that touch it.
- Use glossary terms in issues, tests, and proposals; avoid the synonyms it lists.
- If a needed term is missing, note it for the `domain-modeling` skill rather than inventing one.
- If your change contradicts an ADR, say so explicitly instead of silently overriding it.
